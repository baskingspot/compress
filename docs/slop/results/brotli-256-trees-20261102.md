# Brotli: the tree region at the format's 256 trees, 2026-11-02

The decoder's tree region held 64 trees per category (OQ8's cap) and
refused more with `TooManyTrees`. brotli 1.2.0 writes more than that on
ordinary inputs, so the region now holds the format's ceiling of 256 in
every category and `TooManyTrees` is gone. At 2.6 MiB the one-shot's
state no longer belongs on the stack, so it moved into `decode.Buffer`,
which `decompressBuffered` and `decompressCounted` take from the caller
(`decompress` keeps a stack one as the convenience form). This file has
the streams that tripped the cap, the decode speed before and after, and
the memory.

## Streams over the old cap

The largest counts in any meta-block, read with a debug print in
`frame.readCompressedHeader`, for brotli 1.2.0 (`brotli -q Q [-w 24]`) on
1 MiB of the Zig compiler binary (`bin1m`), 1 MiB and 8 MiB of this repo's
Zig source (`src1m`, `src8m`), 553 KiB of the brotli sources and README
(`mix`), and 5.4 MiB of base64 of random bytes (`b64`):

| stream            | NTREESL | NTREESD | NBLTYPESI |
| ----------------- | ------- | ------- | --------- |
| bin1m q4 w24      | 256     | 24      | 14        |
| bin1m q5 to q9    | 247     | 29–35   | 15–19     |
| bin1m q10 w24     | 197     | 10      | 27        |
| src1m q5 to q9    | 208–234 | 35–41   | 3         |
| src8m q4 w24      | 14      | 101     | 4         |
| src8m q5 to q9    | 247     | 86–106  | 3–6       |
| all q11, mix, b64 | ≤ 60    | ≤ 43    | ≤ 34      |

Literal trees reach 256 and distance trees 106, so both categories need
the ceiling; the command category gets it too, since the format allows it
and the cost is the same kind. Inputs of 128 KiB and less stay under 64
(the most is 50, `bin` at q4), which is why the original sweep never
tripped the cap. Of 63 streams (these inputs at q2 to q11, and 16 to
128 KiB prefixes of `bin1m` and `src1m` at q4 and q5), main refuses 20 with
`TooManyTrees`; with this change all 63 decode to their sources byte for
byte.

## Speed

Base `decode.decompress` (its state on the stack) against this change's
`decode.decompressBuffered` with a static `Buffer`, both into a static
16 MiB target, each file timed as the best of 5 batches of about 30 ms, 12
runs interleaved between the builds,
ReleaseFast for the host CPU, `taskset -c 3`, compared with benchstat.
Base: compress main 2e5eb6b. Inputs (brotli 1.2.0, each decodable by both
builds): a 48-byte payload and 4 KiB of Markdown at q11, 128 KiB of the
binary at q4 and of source at q5, and 1 MiB of each at q11. CPU: Intel
Xeon Processor @ 2.60GHz (4 vCPUs, a cloud VM).

```

                          │   sec/op    │   sec/op     vs base               │
Decompress/b131072-q4.br    799.2µ ± 4%   799.5µ ± 7%       ~ (p=0.114 n=12)
Decompress/bin1m-q11.br     3.931m ± 6%   3.887m ± 7%       ~ (p=0.160 n=12)
Decompress/s131072-q5.br    449.0µ ± 5%   455.2µ ± 6%       ~ (p=0.671 n=12)
Decompress/small-q11.br     6.238µ ± 3%   6.243µ ± 6%       ~ (p=0.977 n=12)
Decompress/src1m-q11.br     3.063m ± 8%   3.049m ± 6%       ~ (p=0.799 n=12)
```

No row moves beyond the runs' spread. The decode path is unchanged; only
the arrays behind it are longer, and they sit behind a pointer the caller
gives. An earlier run of the same rows with the stack form (before the
`Buffer` moved out) gave a geomean of −1.48%, also with no significant
row.

## Memory

The region is reserved, not written: a meta-block writes only the trees it
declares. `frame.Header` grows from 707,204 to 2,732,428 bytes, so
`Reader.DefaultBuffer` goes from 17,484,420 to 19,509,644 bytes (16.7 to
18.6 MiB), `Buffer(22)` from 4.7 to 6.6 MiB, and the one-shot's state,
now `decode.Buffer`, from 709,824 to 2,735,048 bytes. Peak RSS of a
process that decodes one stream (GNU time, the same drivers, base
`decompress` against `decompressBuffered` with a static `Buffer`):

| stream                 | base     | new       |
| ---------------------- | -------- | --------- |
| 48 bytes, q11          | 972 KiB  | 976 KiB   |
| src1m q11              | 2428 KiB | 2440 KiB  |
| bin1m q5 (247 trees)   | refused  | 3088 KiB  |
| src8m q7 w24           | refused  | 10812 KiB |

Resident memory follows the
trees a stream uses, so streams the old cap decoded cost the same; a
caller's `Buffer` reserves 2 MiB more address space than the old region.

Stack: a thread spawned with a 512 KiB stack (macOS's default for
secondary threads) decoding `src1m-q11.br` segfaults on main, whose
`decompress` already carried 709,824 bytes, and decodes it with
`decompressBuffered`. The convenience `decompress` now needs about 4 MiB
of stack.
